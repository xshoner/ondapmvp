## 구현 범위

- src/recommendation/server.ts: 공통 계약의 서버 액션 8개. 고객 추천만 공개하며 관리 기능은 기존 관리자 인증을 먼저 검사한다.
- services.ts: 입력 검증, 오류 코드, 추천/검증 공통 계산 호출, 저장하지 않는 AI 제안.
- local-store.ts: 로컬 JSON 원자적 교체, 파일 락, 기대 updatedAt 비교. 다른 상품 동시 저장에서도 기존 항목을 보존한다.
- database-store.ts: 기존 products / product_evidence / engine_config 사용. 읽기는 서버 전용 클라이언트, 쓰기는 로그인 사용자의 RLS 클라이언트. 조건부 UPDATE에 상품번호와 기존 수정 시각을 넣는다. 첫 저장은 INSERT이며 충돌을 upsert로 덮지 않는다.
- store.ts: 검수 최소 근거 검사, 저장 용량 검사, 단조 증가 수정 시각, 기존 v2 정책 읽기 변환. 과거 level/basis는 그대로 저장하고 v1 추천 가중치는 이관하지 않는다.
- query.ts: 기존 결과 URL과 새 추천 요청 연결. 원래 전체 예산을 개당 예산으로 역산하지 않는다.

기존 운영 화면, 포장 편집기, 안티그래비티 UI 파일을 수정하지 않았다. 새 라이브러리와 DB 마이그레이션을 추가하지 않았다.
