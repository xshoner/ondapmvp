# 안티그래비티 작업 지시서 — 운영 문서와 포장 편집 코드 정리

## 기준과 역할 경계

원격 `codex/core-ui-validation`의 `2800cab9130f854768bed8344aa4aa218f281e94`를 기준으로 별도 worktree와 브랜치 `antigravity/packaging-cleanup-docs`를 만든다. `AGENTS.md`, `START-HERE.md`, `README.md`와 현재 코드를 확인한다. Codex가 동시에 스티커 출력 실패 복구를 수정하므로 **`src/app/packaging/sticker-canvas.tsx` 및 관련 출력 실패 테스트는 수정하지 않는다.** 공유 파일이 불가피하면 이유와 충돌 위험을 명시한다.

운영 DB 변경, 원격 main 푸시, 배포는 하지 않는다. 비밀번호·API 키·환경변수 값을 출력하거나 커밋하지 않는다. 다른 worktree나 사용자의 미커밋 파일을 수정하지 않는다.

## 1. 운영 인계 문서 정리

`START-HERE.md`와 `README.md`의 낡고 서로 충돌하는 현재 상태 설명을 실제 Git 이력과 코드에 맞게 업데이트한다. 운영 배포와 결재 문서 활성화, 추천 1~3위가 종합점수 순위라는 점, 실제 모바일·한컴오피스·관리자 AI 검증의 미확인 상태, 브랜치·검증 명령을 명확히 구분한다. 기존 2026-11-02 기록은 역사로서 가치가 있으면 링크로 보존하되, 이전 시점의 미완료 문구가 현재 상태인 것처럼 보이지 않도록 한다. 배포 성공이나 실환경 검증은 확인한 증거 이상으로 주장하지 않는다. 기존 사용자 문서 `docs/추천-산식-정리.md`는 건드리지 않는다.

## 2. 불필요한 포장 편집 코드 정리

포장 화면 단순화 후 사용되지 않는 props, 변수, 핸들러, 상태와 관련 CSS만 찾아 제거한다. 전체 저장소에서 문자열·동적 참조와 호출부·테스트를 검색하고, 실제 사용자 동작과 저장된 디자인 복원·문구/사진·서식·스티커 인쇄 데이터에 필요한 코드는 유지한다. 기능 삭제, 데이터 모델 변경, 재설계나 의존성 추가는 하지 않는다. 지워도 되는지 확실하지 않으면 유지하고 사유를 보고한다. 추천 결과, 결재, 관리자, 스티커 캔버스 출력 경로는 변경하지 않는다.

## 검증과 보고

`npm test`, `npm run typecheck`, `node node_modules/next/dist/bin/next build --webpack`을 실행하고, 격리 로컬 데이터에서 실제 브라우저로 포장 선택→문구·이미지 변경→미리보기→저장→재조회(기존 디자인 포함)를 확인한다. 코드를 삭제한 이유를 호출 검색 결과와 함께 요약한다. 물리 기기 또는 운영 저장을 수행하지 않았다면 명시한다. 최종 브랜치·기준 및 최종 커밋·변경 파일·검증 결과·미해결 사항을 보고하고 로컬 커밋만 한다. Codex가 결과를 검토하고 통합한다.
