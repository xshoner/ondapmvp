# 온답 추천 엔진 1차 PRD 기초자료

Oct 20, 2026 · @leechee

이번 사업의 1차 목표는 **특허 출원한 '격식지수' 기반 답례품 추천 엔진을 별도 웹서비스로 만들고, 카페24 쇼핑몰 메인에서 실제로 동작하는 것을 12월 20일까지 입증하는 것**입니다. 인쇄물 이미지 생성, 포장 선택 단계, 장바구니 옵션 연동은 내년 고도화로 넘기기로 했습니다.

2026년 10월 20일 심이사와의 1차 회의(52분)를 분석한 내부 검토용 자료입니다. 이 내용을 다듬어 심이사에게 보낼 PRD 초안을 만듭니다.

## 1. 회의에서 결정된 것

회의 초반에는 "추천 + 이미지 생성 + 상용 오픈"이 목표였지만, 중반에 **추천 엔진 중심으로 범위가 좁혀졌습니다**. 심이사의 구체적인 발언은 "격식지수로 3위까지 산출만 돼도 충분하고 이미지는 내년 고도화"(21:03)입니다.

## 2. 개발 범위

이번 계약의 필수 범위는 \*\*1단계(엔진·관리자·검증)와 2단계(카페24 메인 연결)\*\*입니다. 3단계는 일정이 남을 때만 하는 선택 범위로 PRD에 명시해야 합니다. 그래야 결과보고 때 미완성으로 보이지 않습니다.

| 구분 | 기능 | 포함 여부 | 비고 |
| --- | --- | --- | --- |
| 1단계 | 관리자 로그인, 상품 등록·수정·삭제(카페24 URL 기반) | 필수 | 기존 관리자 HTML 시안을 출발점으로 삼음 |
| 1단계 | 상품별 지표 입력(수치·체크·서술형 스토리, 금지 상황) | 필수 | 지표 정의는 특허 자료에 따름 |
| 1단계 | 격식지수 자동 산출 엔진(서술형은 AI가 점수 제안) | 필수 | 이번 사업의 핵심 산출물 |
| 1단계 | 행사 입력 → 상위 3개 추천 매칭 API | 필수 | 제외 규칙(예: 장례 부적합) 포함 |
| 1단계 | 알고리즘 검증 도구(시나리오별 점수 내역 확인) | 필수 | "여러 가지를 눌러봐서 검증"(30:22)에 해당 |
| 2단계 | 고객용 행사 정보 입력 화면(모바일) | 필수 | 비회원 사용 |
| 2단계 | 추천 결과 화면(3개 + 추천 이유) | 필수 | 기존 결과 화면 시안 기준 |
| 2단계 | 카페24 메인 버튼 → 추천 화면 → 카페24 상품 상세 연결 | 필수 | 카페24 디자인 편집 권한 필요 |
| 2단계 | 추천 사용 기록(입력·결과·클릭) 저장 | 권장 | 결과보고서의 실적 자료로 쓸 수 있음 |
| 3단계 | 행사명·문구를 넣은 카드·스티커 이미지 생성 시연 | 선택 | 일정 여유가 있을 때 MVP 수준 |
| 내년 | 추천 → 포장 선택 → 문구 선택 단계형 주문 흐름 | 제외 | 카페24 안에서 가능한지 조사가 먼저 필요 |
| 내년 | 장바구니·주문에 스티커·택 옵션 표시 | 제외 | 카페24 옵션 제약이 큼 |
| 내년 | A3 인쇄 PDF·칼선 자동 출력, 문구 편집기 | 제외 | 심이사 보유 프린터·평판 커터 기준 |
| 내년 | 전화번호로 선물 보내기, 조달·대량 견적, 각인 맞춤 상품 | 제외 | 회의 후반 아이디어 |
| 제외 | 별도 쇼핑몰·결제 구축, 고객 회원 기능 | 제외 | 카페24가 담당 |

## 3. 시스템 구조

회의에서 정한 구조는 **"엔진은 별도로 돈다"**(27:47)입니다. 상품 등록과 결제는 카페24가, 점수·추천은 새 엔진이 맡습니다. 두 시스템은 상품번호와 링크로만 이어집니다.

&#91;embedded content: 시스템 구조 · 카페24, 추천 엔진, 기반 서비스\]

고객은 카페24 메인 버튼으로 추천 화면에 들어오고, 상품을 고르면 다시 카페24 상품 상세로 돌아가 결제합니다. 관리자의 AI 점수 제안도 엔진을 거쳐 AI를 부릅니다.

| 영역 | 제안 | 이유 |
| --- | --- | --- |
| 서버·DB | Supabase(데이터베이스, 로그인, 서버 함수) | 회의에서 말한 서버리스. 점수·가중치처럼 서로 연결된 데이터에 맞음. Firebase도 가능 |
| 화면 | Next.js + Vercel | 고객 화면·관리자를 한 코드로 관리, 무료 구간으로 시작 |
| AI | Claude API | 서술형 → 점수 제안, 추천 이유 문구 |
| 카페24 | 개발자센터 앱 등록 + 상품 조회 API | 상품번호로 상품명·가격·이미지 조회. 등록 절차와 권한 범위는 착수 전 확인 필요 |

## 4. 기능 요구사항

엔진의 정확도는 코드보다 **지표 정의와 가중치**에 달려 있습니다. 그래서 엔진은 가중치를 코드에 박지 않고, 관리자가 바꿀 수 있는 설정값으로 둡니다.

### 4-1. 관리자 (1단계)

- **A-1** 관리자 로그인(초기 1\~3개 계정)
- **A-2** 카페24 상품 URL을 붙여넣으면 상품번호를 추출하고 상품명·가격·대표 이미지를 불러옴
- **A-3** 상품별 지표 입력: 수치형(예: 희소성 1\~10), 선택형(적합 행사·관계), 서술형(생산자 스토리, 인증, 위생)
- **A-4** 금지 상황 지정(예: 장례 부적합). 금지된 행사에는 점수와 관계없이 추천하지 않음
- **A-5** 서술형 입력을 AI가 읽고 지표 점수와 근거를 제안하면, 관리자가 확인·수정 후 확정
- **A-6** 판매 상태(판매 중/품절). 품절 상품은 추천에서 제외
- **A-7** 행사·관계별 가중치와 제외 규칙을 표 형태로 편집

### 4-2. 격식지수·추천 엔진 (1단계)

- **E-1** 상품 격식지수 = 지표 점수 × 행사·관계별 가중치의 합을 100점 만점으로 환산(정확한 식은 특허 청구항에 맞춤)
- **E-2** 추천 순서: 금지 상황·품절·예산 초과 상품을 먼저 걸러내고, 남은 상품을 점수 순으로 상위 3개 반환
- **E-3** 동점 처리 원칙과 조건에 맞는 상품이 3개 미만일 때의 대체 규칙(조건 완화 또는 안내 문구)
- **E-4** 결과에 점수 내역을 포함해 반환(어떤 지표가 몇 점을 만들었는지). 검증·추천 이유 문구에 사용
- **E-5** 추천 이유 문구(ONDAP'S PICK)를 점수 내역을 바탕으로 AI가 작성. 장례 등은 말투 규칙 적용
- **E-6** 같은 입력에는 항상 같은 결과. 순위는 규칙으로 정하고, AI는 순위를 바꾸지 않음(기술성 입증과 설명 가능성을 위해)

### 4-3. 알고리즘 검증 도구 (1단계)

- **V-1** 행사 유형 × 관계 × 예산 조합으로 시나리오를 만들고 저장(예: 8개 행사 × 4개 관계 = 32개)
- **V-2** 시나리오마다 심이사가 기대하는 정답 상품을 입력하고, 엔진 결과와의 일치율을 계산
- **V-3** 가중치를 바꾼 뒤 전체 시나리오를 다시 돌려 일치율 변화를 비교
- **V-4** 결과를 표·이미지로 내보내기(결과보고서·특허 입증 자료용)

### 4-4. 고객용 화면 (2단계)

- **U-1** 행사 정보 입력: 행사 유형, 받는 사람과의 관계, 1개당 예산, 수량, 행사일(항목은 미결, 8장 참고)
- **U-2** 결과 화면: 추천 3개, 격식지수, 추천 이유, 가격·수량 합계. 모바일 우선, 기존 시안의 디자인 따름
- **U-3** 상품을 누르면 카페24 상품 상세 페이지로 이동
- **U-4** 비회원 사용. 이름·연락처 같은 개인정보는 받지 않음
- **U-5** 응답 3초 이내. AI 문구가 늦으면 결과를 먼저 보여주고 문구는 나중에 채움

### 4-5. 카페24 연결 (2단계)

- **C-1** 카페24 메인의 "내 상황에 맞는 선물 찾기" 버튼을 추천 화면으로 연결(링크 또는 스킨에 삽입)
- **C-2** 카페24 개발자센터에 앱을 등록하고 상품 조회 API로 상품 정보를 받음. 가격·판매 상태는 하루 1회 자동 동기화(권장)
- **C-3** 추천 화면 → 카페24 상품 상세 이동 시 유입 표시를 붙여, 추천을 통한 방문을 집계

### 4-6. 데이터 구조 초안

심이사가 말한 "링크에 정보를 심는다"(20:13)는 실제로는 **카페24 상품번호를 열쇠로 엔진 DB에 지표를 저장**하는 방식입니다. 카페24 상품 페이지에는 아무것도 적지 않습니다. PRD에서 이 점을 설명해야 합니다.

| 테이블 | 주요 필드 | 용도 |
| --- | --- | --- |
| products | 카페24 상품번호, URL, 상품명, 가격, 이미지, 지역, 판매 상태 | 카페24에서 불러온 기본 정보 |
| indicators | 지표명, 유형(수치·선택·서술), 범위, 설명 | 특허 자료의 지표 정의 |
| product\_scores | 상품, 지표, 점수, AI 제안 점수, 근거, 확정 여부 | 상품별 지표 값 |
| event\_profiles | 행사 유형, 관계, 지표별 가중치 | 격식지수 계산 설정 |
| exclusions | 상품, 금지 행사·상황 | 제외 규칙 |
| scenarios | 입력 조건, 기대 정답, 최근 결과, 일치 여부 | 알고리즘 검증 |
| recommendation\_logs | 입력 조건, 추천 결과, 클릭 상품, 시각 | 사용 실적·개선 |

## 5. 난이도·공수 추정

1·2단계는 개발자 1명 기준 **약 29\~41일**입니다. 11월 3일\~12월 19일의 작업일은 약 35일이라, 가능하지만 여유가 거의 없습니다. 3단계를 완성 수준으로 더하기는 어렵고, 시연용 PoC까지가 현실적입니다. 아래 일수는 지표 정의가 확정된 것을 전제로 한 추정치입니다.
