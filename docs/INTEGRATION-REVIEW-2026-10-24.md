# 8개 개선 과제의 통합 검토

기준 커밋: bb365db. 작업 브랜치: codex/ondap-integrated-improvements.

| 과제 | 선행 조건·운영 영향 | 구현 결정 |
| --- | --- | --- |
| OD-06 | 주문서는 상품별 추가 입력칸만 제공한다. 같은 상품의 여러 옵션/디자인은 OD-09 주문 항목 API 연결 없이는 확정 매칭할 수 없다. | 수량을 모든 상품 링크에 전달. 여러 상품은 독립 보관. 같은 상품 여러 디자인·여러 주문 행·충돌 입력값은 자동 입력 중단 후 수동 확인. 옵션을 임의로 고르지 않는다. |
| OD-08 | 자동 실행에는 서버 전용 서비스 키·예약 인증과 DB 트랜잭션 함수가 필요. 부분 응답·동시 실행은 상품 누락을 만들 수 있다. | 전체 응답 검증, 시간 제한·재시도, 큰 삭제 거부, 낙관적 버전 검사, 원자 갱신. 설정 전에는 실행하지 않으며 관리자 수동 갱신도 같은 규칙 사용. |
| OD-13 | OD-02의 전체 추천 목적 모델과 OD-07의 실물 포장 규격은 별도 과제. 기존 이미지의 행사는 목적과 다를 수 있다. | 편집기에서 답례/축하 목적을 명시하고 안전한 문구 완성형 제공. 관리자가 행사·목적·상품 적용 대상을 관리. 기존 이미지·고객 편집본은 임의 변경하지 않는다. 실물 호환 검수는 별도임을 표시. |
| OD-30 | 통신 실패 직전 저장됐을 수도 있어 화면 재시도만으로 중복 가능. | 전송 ID로 DB 중복 방지, 성공 응답 후만 완료 기억, 실패 시 입력 유지·재시도. |
| OD-19 | 서버 쿠키 클라이언트를 전역 캐시에 넣으면 사용자 권한 혼합 가능. | React 요청 범위 메모만 사용하고 응답 이후 기록은 Next after로 처리. 가격·품절을 요청 사이에 보관하지 않는다. |
| OD-20 | 원본은 인쇄·캔버스에도 사용된다. | 결과 화면 썸네일만 반응형 최적화. 캔버스 원본과 인쇄 글꼴은 보존. 기존 편집기 동적 로딩을 유지. |
| OD-21 | 상한까지 읽은 행을 합계로 쓰면 과소 집계. 기존 데이터 해석·CSV와 맞아야 한다. | DB에서 전체 기간 집계. 페이지와 CSV는 같은 집계 입구. 구 DB는 정확성 보장 없는 대체 집계를 하지 않고 적용 필요 표시. |
| OD-26 | 관리자 관찰은 DB 장애 시도 유효해야 하며 로그에 개인정보가 없어야 한다. | 허용된 작업명·결과·오류 코드·소요시간만 구조화 기록, 관리자 상태 화면, 외부 점검 CLI, 백업/복원 검증 도구·절차. |

DB 변경은 새 마이그레이션으로만 제공한다. 운영 DB 적용은 저장소 규칙에 따라 사용자가 수행한다. 카페24 기존 스크립트 주소를 유지해 스킨 재편집을 줄인다. main에 배포하지 않고 검증된 브랜치를 검토할 수 있게 제공한다.

검증: 순수 규칙 단위 검사 → DB 권한·동시성·집계·중복 검사 → 타입/빌드 → 로컬 고객·관리자·카페24 모의 연결 → 화면 확인. 운영 설정·실결제·실기기·실물 출력은 별도 점검표로 남긴다.
