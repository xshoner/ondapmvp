# 안티그래비티 작업 지시서: 모바일 포장·메시지 꾸미기

## 작업 기준과 역할 경계

`ondap-mvp` 원격 `codex/core-ui-validation` 브랜치의 `f9cb7d0689261e02eaf74a4510ab30234e071266`을 기준으로 별도 worktree와 브랜치 `antigravity/mobile-packaging-fix`에서 시작한다. `START-HERE.md`와 `AGENTS.md`를 먼저 읽고 현재 실제 코드와 호출 관계를 확인한다. 다른 worktree와 변경 중인 파일을 건드리지 않는다. 환경변수와 비밀값은 보고서·커밋에 포함하지 않는다.

Codex가 결재 문서와 행사 선택 UI를 동시에 수정하므로 **`src/approval/**`, `src/app/approval/**`, `src/app/api/approval/**`, `src/app/recommendation-ui/**`, `src/recommendation/**`, `src/cafe24/**`, `src/ai/**`는 수정하지 않는다.** 포장 영역과 꼭 필요한 공통 저장·이미지 처리 코드 및 관련 테스트만 수정한다. 공통 파일을 수정해야 한다면 충돌 가능성과 이유를 보고한다. 운영 DB 수정, 운영 배포, main 푸시는 하지 않는다.

## 목적

고객이 모바일에서 포장 선택부터 메시지 꾸미기, 스티커 미리보기, 디자인 저장과 다음 단계까지 오류 없이 진행할 수 있도록 고친다. 고객 관점에서 간단하게 만들고 개발자용 문구나 불필요한 기능은 노출하지 않는다.

## 필수 작업

1. 모바일의 스티커 미리보기 로드 오류와 디자인 저장 실패를 **실제 재현하고 원인을 추적**하여 수정한다. `src/app/packaging/packaging-editor.tsx`, `sticker-canvas.tsx`, `components/preview-pane.tsx`, `actions.ts`, 저장소 및 이미지 로딩·캔버스 내보내기 경로를 살핀다. 브라우저 오류, 이미지 CORS, 동적 모듈 로드, 모바일 크기·메모리, 저장 검증 및 서버 응답 중 실제 원인을 확인하고 그에 맞게 고친다. 원인을 모르면 추측해서 통과 처리하지 말고 증거와 미해결 상황을 보고한다. 이미지 보안 검증·저장 검증을 제거하거나 오류를 성공으로 속이지 않는다.
2. 모바일 메시지 꾸미기 화면이 가로로 넘치거나 잘리지 않고, 미리보기·조작 버튼을 터치할 수 있게 구성한다. 320/375/390/430px 폭 및 데스크톱을 확인하고, 가로 스크롤 없이 키보드가 열린 상황도 점검한다. 미리보기와 편집 기능을 포기하지 않는다.
3. 메시지 꾸미기 메뉴에 고객이 필요한 기능만 남긴다. (a) 함께 제작할 인쇄물 선택 및 인쇄물 없음, (b) 추천 이미지 적용·삭제, (c) 추천 문구 적용·삭제, (d) 미리보기에서 문구 직접 편집, (e) 이미지 직접 등록. 문구 편집에는 폰트·글자 크기·글자색·외곽선·그림자를 기본 제공한다. 이미지를 선택하거나 제거해도 문구가 사라지지 않고, 문구를 삭제하거나 수정해도 이미지가 사라지지 않아야 한다. 저장한 디자인을 재조회할 때 편집 내용이 유지되어야 한다.
4. 기존 고객 디자인, 저장 데이터 모델과 인쇄 결과 호환성을 보존한다. 단순화는 불필요한 **UI 노출**부터 처리하고, 기존 저장본에 필요한 필드·렌더링 로직을 무분별하게 삭제하지 않는다. 사용자 입력을 자동으로 덮어쓰거나 기존 디자인을 손실하지 않는다. 오류 시 현재 편집 내용을 유지하고 고객이 재시도할 수 있어야 한다.

## 검증 및 보고

- 격리된 로컬 또는 시험 저장소에서 실제 브라우저로 `고객 추천 → 포장 선택 → 인쇄물 선택 → 추천 이미지/문구 적용 및 개별 삭제 → 미리보기 직접 편집 → 폰트·크기·색·외곽선·그림자 변경 → 이미지 등록 → 저장 → 다음 단계 → 저장본 재조회`를 검증한다. 인쇄물 없음 경로도 확인한다.
- 모바일 폭 320/375/390/430px과 데스크톱에서 가로 넘침, 터치 조작, 저장과 출력 이미지를 확인한다. 에뮬레이션은 물리 기기 검증으로 주장하지 않는다. 물리 기기가 없으면 미실시라고 명시한다.
- 실패한 이미지 및 저장 요청 시 입력 유지·재시도, 기존 디자인 재조회, 고객 조건(상품·수량·예산) 보존을 확인한다. 실제 원인을 검증하는 의미 있는 테스트를 추가하고 `npm test`, `npm run typecheck`, `node node_modules/next/dist/bin/next build --webpack`을 실행한다.
- 브랜치·부모와 최종 커밋, 변경 파일, 재현한 원인, 실제 검증 결과와 미실시 사항을 보고한다. 스크린샷/로그는 민감정보 없이 제공한다. 커밋만 하고 푸시·배포는 하지 않는다. Codex가 결과를 검토하고 통합한다.
