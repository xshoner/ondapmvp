# 안티그래비티 개발 지시서 — 미리보기 문구 직접 편집

## 기준과 작업 분리

원격 `codex/core-ui-validation`의 커밋 `6ef1a899e40745de0d529a22fda4b75111bd133a`을 기준으로 별도 worktree와 브랜치 `antigravity/inline-sticker-text`를 만든다. `START-HERE.md`, `AGENTS.md`와 실제 기존 코드·호출 관계를 먼저 읽는다.

Codex가 동시에 단계명, 섹션 순서, 배경색을 수정한다. **`src/app/packaging/components/step2-message.tsx`, `step-navigation.tsx`, `step1-wrapping.tsx`는 수정하지 않는다.** 미리보기의 `src/app/packaging/components/preview-pane.tsx`, `src/app/packaging/sticker-canvas.tsx`와 직접 관련 테스트를 우선 수정한다. 필요할 때만 다른 공통 파일을 최소한으로 수정하고 사유를 보고한다. 운영 DB 변경, main 푸시, 배포는 하지 않는다. 비밀값을 출력·커밋하지 않는다.

## 목표

고객이 스티커 미리보기에서 **보이는 문구를 직접 터치하거나 클릭하여 그 자리에서 수정**할 수 있게 한다. 기존 미리보기 아래의 `선택한 문구 편집` 별도 텍스트 영역은 삭제한다. 입력창이 미리보기 틀에 가려지거나 모바일 키보드에 가려져 수정할 수 없는 상황을 해결한다.

## 필수 동작

1. 미리보기에서 문구를 누르면 해당 문구 위치에 실제 텍스트 입력이 시작된다. 고객이 별도 메뉴·편집란을 찾아가지 않아야 한다. 단일 탭/클릭으로 작동해야 하며, 한글 IME 조합·줄바꿈을 지원하고 내용을 타이핑하는 동안 유실하거나 중복하지 않는다. 입력 중 글자가 보이도록 폰트 크기·위치·대비를 확보한다.
2. 다른 곳 선택, 완료 또는 포커스 이탈 후 편집 내용을 보존한다. 오류나 입력 취소 상황에서 기존 문구를 뜻하지 않게 지우지 않는다. 기존 120자 제한 및 각 레이어의 데이터 검증을 존중한다. 모바일·PC에서 터치/마우스 드래그를 통한 위치 이동과 글자 선택, 크기·회전 기능도 유지한다. 탭과 드래그를 구분해 조작이 충돌하지 않게 한다.
3. 추천 문구 선택, 직접 입력, 글자 서식(폰트·크기·색·외곽선·그림자), 추천 이미지/업로드·삭제, 저장 후 불러오기 및 인쇄 PNG가 같은 최신 내용을 사용해야 한다. 기존 디자인과 이름/날짜 레이어 및 사진을 훼손하지 않는다. 고객 입력과 추천 조건을 보존한다.
4. 모바일에서 320/375/390/430px과 데스크톱 폭을 확인한다. 입력 영역이 화면·미리보기·키보드에 잘리지 않는지, 확대/스크롤 후에도 편집이 가능한지 확인한다. 접근성 이름과 키보드 입력/포커스도 제공한다.
5. 테스트에서는 실제 브라우저로 미리보기 문구를 클릭·터치하고 한글 및 줄바꿈을 입력해 캔버스에 반영되는지, 이미지 적용과 서식 변경 후에도 내용이 보존되는지, 저장·재조회와 내보내기가 같은 내용인지 확인한다. 모바일 에뮬레이션과 물리 기기 검증을 구분한다. 실패 시 원인과 재현 방법을 보고하고 미검증을 통과로 기록하지 않는다.

`npm test`, `npm run typecheck`, `node node_modules/next/dist/bin/next build --webpack`을 실행한다. 작업을 커밋하고 브랜치·기준 커밋·최종 커밋, 변경 파일, 실제 브라우저 검증과 미실시 사항을 보고한다. 검토·통합·배포는 Codex가 진행한다.
